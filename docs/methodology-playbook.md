# SkillGate 方法论执行手册

**所有步骤都严格按照 LGD 三律 + 四道闸门执行。**

---

## 📚 方法论总纲

### LGD 三律（核心）

| 律 | 含义 | 在开发中怎么执行 |
|----|------|-----------------|
| **📇 有籍** (Registered) | 每个动作都有档案可追溯 | 每个版本有 CHANGELOG，每次扫描有审计日志，每个功能有 commit |
| **📜 有证** (Evidenced) | 每个结论都有出处有证据 | 每个 finding 有 file+line+rule_id+explanation，每个功能有测试 |
| **🚪 有门禁** (Guarded) | 关键节点有检查有验证 | 每个功能写完先跑测试，每个版本发布前先跑全量测试 |

### 四道闸门（发布前检查）

| 闸门 | 什么时候过 | 检查什么 |
|------|-----------|----------|
| **落地闸** | 开发前 | 有没有可执行方案？不要做 PPT 项目 |
| **身份闸** | 提交前 | 作者信息准确吗？license 清楚吗？ |
| **时效闸** | 发布后 | 有没有持续监控？分数暴跌有告警吗？ |
| **留痕闸** | 每次操作后 | 结果有存档吗？历史能追溯吗？ |

## 🔄 开发流程每一步的方法论映射

### 步骤 1：需求分析

| 方法论 | 怎么执行 |
|--------|---------|
| 有籍 | 记录需求来源（用户说的），记录在 CHANGELOG 里 |
| 有证 | 每个需求都有用户原话作为证据 |
| 有门禁 | 需求分析完，先写最小可行方案，不要直接写代码 |

### 步骤 2：架构设计

| 方法论 | 怎么执行 |
|--------|---------|
| 有籍 | 设计文档存档（competitive-analysis.md） |
| 有证 | 每个设计决策都有竞品对比作为证据 |
| 有门禁 | 设计完先过"四道闸门"检查，再动手写代码 |

### 步骤 3：写代码

| 方法论 | 怎么执行 |
|--------|---------|
| 有籍 | 每个功能单独 commit（我们现在没 git，但是有 CHANGELOG） |
| 有证 | 每个功能配单元测试作为证据 |
| 有门禁 | 写完一个功能，立刻跑测试，不过就改 |

### 步骤 4：测试

| 方法论 | 怎么执行 |
|--------|---------|
| 有籍 | 测试报告存档（external-user-test-report.md） |
| 有证 | 每个 bug 都有复现步骤 + 修复方案 |
| 有门禁 | 全部测试通过才能算完成 |

### 步骤 5：发布

| 方法论 | 怎么执行 |
|--------|---------|
| 落地闸 | 有可执行的 Demo 才发布 |
| 身份闸 | 作者 + license + version 都清楚 |
| 时效闸 | 配 skillwatch 持续监控 |
| 留痕闸 | CHANGELOG + 审计日志都有记录 |

## ✅ 现在每一步都做到了吗？

| 步骤 | 落地闸 | 身份闸 | 时效闸 | 留痕闸 |
|------|--------|--------|--------|--------|
| 需求分析 | ✅ | ✅ | — | ✅ |
| 架构设计 | ✅ | ✅ | — | ✅ |
| 写代码 | ⚠️ | ✅ | — | ⚠️ |
| 测试 | ✅ | ✅ | — | ✅ |
| 发布 | ✅ | ✅ | ✅ | ✅ |

### 哪里没做到位？

**写代码阶段**: 边写边改，没有严格的"每个功能写完先测试再合并"。我是一口气写很多，最后一起测。

**怎么补？**
- 加一个 `pre-commit` 检查：写代码前先跑测试
- 加一个 `checklist.md`：每次发布前对着检查

## 📋 发布前检查清单（四道闸门）

每次发布新版本前，对着这个清单打勾：

### 落地闸
- [ ] 有没有可执行的 Demo？
- [ ] 核心功能都能跑吗？
- [ ] 有没有 crash 或报错？

### 身份闸
- [ ] README 里有作者信息吗？
- [ ] 有 LICENSE 吗？
- [ ] 有 version 号吗？

### 时效闸
- [ ] 配了持续监控吗？
- [ ] 分数暴跌有告警吗？
- [ ] 有趋势图吗？

### 留痕闸
- [ ] CHANGELOG 更新了吗？
- [ ] 审计日志有记录吗？
- [ ] 测试报告存档了吗？

---

## 🎯 核心原则

**每个动作都要有籍、有证、有门禁。**

- 做了什么 → 写 CHANGELOG（有籍）
- 为什么这么做 → 写设计文档（有证）
- 做完怎么验证 → 跑测试（有门禁）

**这样不管过多久回头看，都能说清楚：什么时候、谁、做了什么、为什么、怎么验证的。**
